# Application inputs are normalized before validation

Payment application use cases normalize `Command` and `Query` inputs before validating them, using one app-boundary function per input type that returns the normalized public input type or a gateway-owned `InvalidInput` error. The code expresses this boundary step through public `New...Command` and `New...Query` constructors that create prepared command/query values. Those prepared values keep parsed domain identifiers in domain types and keep fields unexported when construction must be enforced. This keeps use-case behavior based on canonical values, keeps idempotency fingerprints stable for equivalent caller input, and avoids spreading validation checks through the body of each use case. HTTP handlers still own protocol-shape validation such as media type, malformed JSON, unexpected bodies, and unknown query parameters; app use cases own command/query value validation.
