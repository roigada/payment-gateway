# Graceful HTTP shutdown

On SIGINT or SIGTERM, the gateway stops accepting new HTTP requests and immediately cancels request-owned work before beginning a configurable `SHUTDOWN_TIMEOUT` (default `30s`) drain. This prevents an in-flight Payment command from starting another external side effect, including an automatic Mock Bank retry, after the gateway begins shutdown. Commands that already persisted a Bank Operation Key recover safely through existing Idempotency Key semantics. `GET /readyz` becomes unavailable immediately when draining starts so traffic is removed promptly, while `GET /healthz` remains successful until the process exits because it represents process liveness rather than traffic eligibility. The timeout must be a positive duration so it cannot accidentally disable bounded termination. A second SIGINT or SIGTERM skips the remaining drain period and force-closes connections, providing an operator escape hatch. Structured lifecycle logs record signal receipt, drain start and timeout, clean completion, deadline-expiration forced closure, and operator-requested forced closure; those events make deployment interruption diagnosable without adding a new metrics surface. The local Compose service uses a 35-second stop grace period, leaving a small buffer beyond the default drain window before Docker force-kills the process.
