# Graceful HTTP shutdown

On SIGINT or SIGTERM, the gateway stops accepting new HTTP requests and allows already-started requests up to a configurable `SHUTDOWN_TIMEOUT` (default `30s`) to finish before force-closing remaining connections. This gives Payment commands a bounded opportunity to persist their final outcome and idempotency response while ensuring orchestration can eventually replace the process. `GET /readyz` becomes unavailable immediately when draining starts so traffic is removed promptly, while `GET /healthz` remains successful until the process exits because it represents process liveness rather than traffic eligibility. The timeout must be a positive duration so it cannot accidentally disable bounded termination. A second SIGINT or SIGTERM skips the remaining drain period and force-closes connections, providing an operator escape hatch. Structured lifecycle logs record signal receipt, drain start and timeout, clean completion, deadline-expiration forced closure, and operator-requested forced closure; those events make deployment interruption diagnosable without adding a new metrics surface. Signal receipt does not itself cancel in-flight request contexts: started Payment commands may finish until the drain deadline, then the forced close may interrupt them and existing idempotency plus Bank Operation Key recovery handles the unknown outcome. The local Compose service uses a 35-second stop grace period, leaving a small buffer beyond the default drain window before Docker force-kills the process.
